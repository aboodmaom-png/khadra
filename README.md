# خضرة براند — المتجر ولوحة التحكم

HTML/CSS/JS بدون framework، Firebase (Firestore + Auth للأدمن بس)، صور المنتجات على Cloudinary.

## الصفحات
| الصفحة | شو فيها |
|---|---|
| `index.html` | الرئيسية: ٥ مشاهد بالخلفية + الأقسام + الأكثر طلباً + كيف بتطلب |
| `shop.html` | كل المنتجات، فلتر بالقسم (`?cat=`)، بحث وترتيب |
| `product.html?id=` | الصور والفيديو، الأحجام، الكمية، أضف للسلة |
| `cart.html` | السلة + بيانات الزبون + المنطقة + الدفع + إرسال الطلب |
| `track.html?t=` | صفحة "وصلنا طلبك" وتتبع الحالة (بتتحدث لحالها) |
| `admin.html` | لوحة التحكم (بتنزل عالموبايل كتطبيق) |
| `tools/seed.html` | تعبئة البيانات الأولى، للمطوّر بس (ما بتنرفع) |

## المجلدات
```
public/css/site.css, admin.css
public/js/fb.js            تشغيل Firebase و Firestore (نسخة الـ SDK بمكان واحد)
public/js/fb-auth.js       تسجيل الدخول، للوحة التحكم و seed بس (المتجر ما بيحمّله)
public/js/fancy-select.js  قوائم الاختيار بشكل البراند (بتشتغل لحالها على أي select)
public/js/util.js          حماية النصوص، العملة، الواتساب، التواريخ
public/js/constants.js     حالات الطلب، طرق الدفع، رسائل الواتساب الافتراضية
public/js/site/*.js        كود صفحات المتجر
public/js/admin/*.js       كود لوحة التحكم (orders, products, catalog, settings, upload)
public/assets/scenes/      صور المشاهد الخمسة (عمودي للموبايل، عريض للابتوب)
public/assets/brand/       اللوجو وأيقونات التطبيق
public/assets/demo/        صور تجريبية (بتتبدّل بصور حقيقية)
```

## التشغيل والنشر
1. Firestore و Authentication (Email/Password) مفعّلين، وفي مستند بـ `admins/{UID}` لكل أدمن.
2. القواعد والفهارس:
   ```
   firebase deploy --only firestore:rules,firestore:indexes
   ```
3. أول دخول للوحة التحكم بيعمل الأساسيات لحاله إذا ناقصة (عدّاد الطلبات، الإعدادات، نصوص المشاهد).
   للبيانات التجريبية: افتح `public/tools/seed.html` بـ Live Server وكبس "ضيف التجريبي".
4. جرّب محلياً (Live Server): اطلب من `cart.html`، وأكّد من `admin.html`.
5. النشر:
   ```
   firebase deploy --only hosting
   ```

**لا تشغّل `firebase init` على هالمجلد.** ممكن يكتب فوق `firestore.rules` و `firestore.indexes.json`.

## حياة الطلب
1. الزبون بيطلب: transaction وحدة بتعمل `orders/KH-####` + `orderStatus/{trackId}` وبتزيد العدّاد. القواعد بترفض أي رقم غلط، أو منطقة مش مفعّلة، أو رسوم توصيل غلط، أو متجر مسكّر.
2. **تأكيد** (لوحة التحكم): بيختار الموعد، بيخصم من المخزون (الأصناف اللي بتنعمل عالطلب ما بتنخصم)، بيسجّل بـ `stockLog`، بيحدّث صفحة التتبع، وبيطلع زر رسالة واتساب جاهزة. إذا الأسعار تغيّرت من وقت الطلب بيخيّرك.
3. **طلع للتوصيل**: لطلب واحد أو لمجموعة (مع نسخ قائمة السائق).
4. **وصل وانقبض** / **وصل والدفع لسا**: بيسجّل بـ `sales` و `customers`.
5. **إلغاء**: بيرجّع المخزون اللي انخصم (إلا إذا اخترت لا).

## السرعة والنت الضعيف
صفحات المتجر بتطلع فوراً: الهيدر والفوتر ما بيستنوا النت، والأقسام والمنتجات والمناطق والإعدادات بتنعرض من آخر نسخة محفوظة على جهاز الزبون (localStorage) وبتتحدث لما توصل الجديدة. السلة ما بتبعت الطلب إلا بعد ما توصل الأسعار الجديدة من النت.

## المخزون
كل منتج إله `unit` و `stock`، وكل حجم إله `use` = قديش بياكل من الوحدة (مرطبان ٥٠٠ غ والمخزون بالكيلو → 0.5).
"+ دفعة" بتزيد المخزون وبتحدّث "عُبّي بتاريخ" بصفحة المنتج.

## المرحلة الثانية (لسا)
قائمة التحضير، سجل الدفعات والمخزون كصفحة، ركّب علبتك، الكوبونات، صفحة الزباين، التقييمات، أرقام الأسبوع، تعديل نصوص المشاهد من اللوحة.
